# Boogbe — Data Model

**Status:** Draft for owner review · 2026-10-09
Source of truth once M0 lands: `prisma/schema.prisma` + `prisma/migrations`. This document is the design; keep it in sync when the schema changes (same PR).

## Conventions

- Postgres 16. IDs: `text` primary keys generated app-side as UUIDv7 (`uuidv7` package) — sortable by time; Better Auth tables use Better Auth's own string ids.
- Every tenant table has `org_id text not null references organization(id)` as its **first** column after `id`, an index leading with `org_id`, RLS enabled + forced (see ARCHITECTURE §3.3).
- Money: `bigint` kobo, column suffix `_kobo`. Percentages: `int` basis points, suffix `_bps`.
- Stay dates: `date` (`check_in`, `check_out`, half-open). Instants: `timestamptz` (`created_at`, `updated_at` on all tables).
- Soft delete is **not** used for money or bookings (status fields instead). `active boolean` for catalogue items (properties, units, fees, templates).
- Enums are Postgres enums generated by Prisma; their TS mirrors live in `packages/shared/src/enums.ts`.
- Prisma model names PascalCase, table names snake_case via `@@map`.

## Global tables (no RLS)

| Table | Owner | Notes |
|---|---|---|
| `user`, `session`, `account`, `verification` | Better Auth | `user.role` = `admin` (platform admin, via admin plugin) or `user` |
| `organization` | Better Auth org plugin | **The operator.** Additional fields: `timezone` (default `Africa/Lagos`), `currency` (`NGN`), `status` (`active`/`suspended`), `contact_email`, `contact_phone`, `whatsapp_phone`, `address`, `logo_key` |
| `member` | Better Auth | `role` ∈ admin/frontdesk/housekeeper/landlord |
| `invitation` | Better Auth | `role`, `expires_at` |
| `login_attempt` | auth module | lockout bookkeeping (AUTH-02) |
| `job_run` | worker | cron observability |

## Tenant tables (RLS)

### Settings & counters
**`org_settings`** (1 row per org): `check_in_time` (`time`, 14:00), `check_out_time` (12:00), `hold_hours` (24), `auto_confirm_on_payment` (true), `owner_sees_guest_names` (false), `receipt_prefix`, `statement_prefix`, `booking_prefix`.

**`org_counter`**: `(org_id, name)` PK; `value bigint`. Names: `receipt`, `statement`, `booking`.

### Inventory
**`owner`**: `id, org_id, name, phone, email, bank_name, account_number, account_name, notes, user_id (nullable → user.id), active`.

**`property`**: `id, org_id, name, address, area, default_owner_id (nullable → owner), fee_type (pct_gross|pct_net|none), fee_bps, fee_fixed_monthly_kobo, notes, active, sort_order`.

**`unit`**: `id, org_id, property_id, name, bedrooms, max_guests, nightly_rate_kobo, default_assignee_member_id (nullable), check_in_instructions (text), fee_override (boolean), fee_type, fee_bps, fee_fixed_monthly_kobo (used only when fee_override), active, sort_order`. Unique `(org_id, property_id, name)`.

**`unit_ownership`** (effective-dated, OWN-07): `id, org_id, unit_id, owner_id (nullable = operator-owned), effective_from date, effective_to date null`. Exclusion constraint: no overlapping ranges per unit. The "current" owner shown in UI = row covering today; when a property's default owner changes, rows for units without their own override are closed and reopened.

**`unit_fee`**: `id, org_id, unit_id, kind (caution_deposit|cleaning|extra_guest|other), label, amount_kobo, basis (per_stay|per_night|per_guest_night), included_guests int null, refundable bool, active`.

**`block`**: `id, org_id, unit_id, start date, end date (exclusive), source (manual|ical), reason (maintenance|owner_stay|other|external), note, feed_id null, external_uid null, external_summary null`. Unique `(feed_id, external_uid)` where source = ical. Manual blocks: exclusion constraint among manual blocks per unit.

### Guests & bookings
**`guest`**: `id, org_id, full_name, phone_e164, email null, notes, anonymised_at null`. Indexes: `(org_id, phone_e164)`, `(org_id, lower(email))`, trigram on `full_name` (`pg_trgm`).

**`booking`**: `id, org_id, ref (unique per org), unit_id, guest_id, check_in date, check_out date, guest_count int, source (whatsapp|phone|walk_in|direct|airbnb|booking_com|other), status (tentative|confirmed|checked_in|checked_out|cancelled|no_show), hold_until timestamptz null, computed_total_kobo, final_total_kobo, override_reason null, ical_warning_ack bool, notes, cancelled_at, cancel_reason, checked_in_at, checked_out_at, created_by_member_id`.
Constraints:
```sql
CHECK (check_out > check_in)
EXCLUDE USING gist (
  unit_id WITH =,
  daterange(check_in, check_out, '[)') WITH &&
) WHERE (status IN ('tentative','confirmed','checked_in'));
```
(`CREATE EXTENSION IF NOT EXISTS btree_gist;` in the first migration.)

**`booking_line`**: `id, org_id, booking_id, kind (accommodation|fee|deposit|discount|adjustment), fee_kind null, label, quantity numeric(10,2), unit_amount_kobo, amount_kobo, refundable bool, recognition (per_night|on_check_in)`. Snapshot at create/reprice. `final_total_kobo = Σ amount where kind != deposit`.

**`booking_status_event`**: `id, org_id, booking_id, from_status, to_status, actor_member_id, reason, at`.

### Money
**`payment`** (append-only; app role has INSERT/SELECT only): `id, org_id, booking_id, kind (payment|refund|deposit_received|deposit_returned|deposit_withheld|void), amount_kobo (>0), method (bank_transfer|cash|pos|card|paystack|other), received_on date, reference, external_ref null, note, receipt_no null, voids_payment_id null, recorded_by_member_id, created_at`.
- `void` rows reference the voided entry; a voided entry is excluded from all sums.
- `deposit_withheld.note` required.

### iCal
**`ical_feed`**: `id, org_id, unit_id, label, channel (airbnb|booking_com|vrbo|other), url, etag, last_modified, last_synced_at, last_status (ok|error|never), last_error, consecutive_failures, active`.

**`ical_export`**: `id, org_id, unit_id, channel, token (unique, 32 bytes base64url), exclude_feed_id null, created_at, rotated_at`. Public lookup by token happens via a `SECURITY DEFINER` function `ical_export_lookup(token) returns (org_id, unit_id, export_id)` so the public route can then set `app.org_id`.

**`sync_conflict`**: `id, org_id, unit_id, booking_id, block_id, status (open|resolved), resolution (external|cancelled_booking|moved_booking) null, resolved_by_member_id, resolved_at`. Unique `(booking_id, block_id)`.

### Messaging
**`message_template`**: `id, org_id, key (booking_confirmation|payment_receipt|check_in_details|pre_arrival_reminder|post_checkout_thanks|deposit_returned), email_subject, email_body (markdown), whatsapp_body, auto_email bool, active`. Unique `(org_id, key)`.

**`outbound_message`** (outbox + log): `id, org_id, booking_id null, template_key, channel (email|whatsapp), recipient, subject, body_rendered, status (queued|sent|failed|whatsapp_opened), attempts, next_attempt_at, provider_id, error, actor_member_id null, created_at, sent_at`.

### Tasks
**`task`**: `id, org_id, unit_id, booking_id null, type (turnover|cleaning|maintenance|inspection), title, notes, due_at timestamptz, assignee_member_id null, priority (low|normal|high), status (todo|in_progress|done|cancelled), completed_at, created_by_member_id null`. Partial unique `(booking_id) WHERE type = 'turnover'`.

**`task_photo`**: `id, org_id, task_id, file_key, uploaded_by_member_id, created_at`.

### Owners & statements
**`expense`**: `id, org_id, property_id, unit_id null, incurred_on date, category, amount_kobo, description, receipt_file_key null, charge_to_owner bool, allocation_method (direct|equal|custom), recorded_by_member_id`.

**`expense_allocation`**: `id, org_id, expense_id, unit_id, share_bps, amount_kobo`. Σ amount = expense.amount (enforced in service + test).

**`statement`**: `id, org_id, number, owner_id, period (date = first of month), status (draft|finalised|paid), figures jsonb (StatementFigures snapshot), gross_kobo, expenses_kobo, fee_kobo, fixed_fee_kobo, opening_balance_kobo, net_payout_kobo, pdf_file_key null, finalised_at, finalised_by_member_id, paid_on, payout_reference`. Unique `(owner_id, period)`. App role cannot UPDATE rows where status ≠ draft except the `paid_on`/`payout_reference`/`status='paid'` transition (enforced by trigger).

### Platform-wide utilities
**`notification`**: `id, org_id, user_id, kind, title, body, link, read_at, created_at`.

**`audit_log`** (append-only): `id, org_id, actor_user_id, actor_member_id, action, entity, entity_id, before jsonb, after jsonb, ip, user_agent, at`.

**`file`**: `id, org_id, key, kind (logo|receipt_image|task_photo|statement_pdf|receipt_pdf), content_type, size_bytes, uploaded_by_member_id, confirmed bool, created_at`.

## Relationships (summary)

```
organization 1─* member, invitation, org_settings(1), every tenant table
property 1─* unit 1─* unit_fee, unit_ownership, block, ical_feed, ical_export, booking, task
owner 1─* unit_ownership, statement ; property.default_owner_id → owner
guest 1─* booking 1─* booking_line, payment, booking_status_event, outbound_message, sync_conflict, task
expense 1─* expense_allocation
```

## Migration rules
1. One migration per change; never edit an applied migration.
2. Raw SQL (RLS policies, grants, exclusion constraints, extensions, triggers) lives in the same migration directory as the Prisma-generated SQL, appended to `migration.sql`.
3. Every new tenant table migration must include: `ENABLE` + `FORCE ROW LEVEL SECURITY`, the `org_isolation` policy, grants to `boogbe_app`. `rls-coverage.spec.ts` fails otherwise.
4. Only the schema owner (see `docs/COORDINATION.md`) merges changes to `prisma/schema.prisma`.
